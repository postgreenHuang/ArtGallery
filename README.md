# 拾色 Atelier

一个 TypeScript + React + Tauri 2 的私人艺术画廊。以对话寻找开放馆藏，将喜欢的作品留在本地画架中。界面使用暖白纸色、鼠尾草绿、衬线标题和留白展墙。

**开发状态（2026-10-27）**：来源页文字补充、逐件 AI 复核、首轮检索预算和跨轮条件修订已接入。Brave 搜索可在偏好中单独开启、配置密钥，资料库记录每月请求次数。画架作品在空闲时自动补下原图，作品右键菜单可定位本地文件或在 Windows 上设置桌面壁纸。真实模型／Brave 密钥联调和完整原生体验评测仍待完成。执行范围与剩余工作见 [执行进度](docs/evaluation/implementation-progress.md)。

## 启动

需要 Node.js 22+、Rust stable；Windows 需要 Microsoft C++ Build Tools 和 WebView2。

```powershell
npm install
npm run tauri dev
```

浏览器预览：`npm run dev`，打开 http://127.0.0.1:1420。浏览器使用 IndexedDB，支持开放馆藏检索、对话历史和离线收藏；系统文件夹、密钥和 AI 请求只在桌面版启用。不同馆藏的浏览器跨域策略可能影响预览，桌面版通过受限的本地请求访问官方接口。

构建独立桌面程序：

```powershell
npm run tauri build -- --debug --no-bundle
```

移除 `--debug` 可构建 release。当前不生成安装器、不做代码签名。Windows 可执行文件在 `src-tauri/target/debug/atelier-gallery.exe` 或 `src-tauri/target/release/atelier-gallery.exe`；两个版本启动时都不显示控制台窗口。

## 使用

- **发现艺术**：从 Wikimedia Commons、克利夫兰艺术博物馆和芝加哥艺术博物馆轮换选画，“换一组画作”会轮换搜索结果分页，优先展示本次使用期间尚未见过的作品；候选作品耗尽时可能重新出现。“查看相似”会以所选作品开启灵感推荐对话。设置中的 Google Art Project / 全部 Commons 选项只影响 Wikimedia 的检索范围。
- **灵感寻画与持续对话**：AI 先判断是搜索还是讨论，明确作者、必须条件、偏好与排除项，再检索真实结果。指定作者时按作者字段核对并过滤无关作品，分页保留同样约束；无结果时不会用其他艺术家凑数。候选经逐件复核后形成展墙和编号：证据明确的不符项进入可查看的排除记录，证据不足的作品保留并标为待核实；分页也执行复核。AI 依据最终展墙回答。可以直接问“第三张是谁画的”“比较第一张和第二张”“这些为何不符合要求”；讨论已有结果不会自动再搜。会话保留最近 8 条消息及最近一组搜索结果，连续追问时仍能引用这组作品。
- **每幅画的选择原因**：卡片下方显示一句简短理由；AI 解读时依据本次实际作品资料逐件给出，作者匹配或关键词候选等实际检索依据另行保留。未附图的作品不接受视觉判断理由。AI 失败时仍显示检索依据；发现艺术注明轮换画家和是否重访。原因随作品及对话保存，后续追问会带上这些依据。旧记录没有保存理由时明确提示缺失。
- **更多搜索来源**：加入大都会艺术博物馆（Met），使用其分页搜索与公开作品图片。可在“AI 与检索”开启全网搜图并保存独立的 Brave Search API Key；桌面端检索图片线索，展示缩略图和来源页，AI 同样能读取这些线索。网页结果单独标记为“作者与授权待核实”，不当作已验证馆藏或可下载原图。无需搜索密钥也可使用馆藏与“在 Google 图片中继续找”链接。全网搜图关闭时不请求 Brave。

- **作品讲解**：在作品上右键选择“展开讲解对话”，首次打开会主动介绍时代背景、作者、技法和风格；已开启 AI 时结合馆藏资料与画面生成导览，否则先展示谨慎的馆藏资料概览。随后可以持续追问。同一作品再次打开会接续原对话；历史中的“作品讲解”和“灵感寻画”分开浏览。
- **无需密钥也能使用**：直接检索模式内置常见中文艺术家与主题映射。复杂中文描述、上下文指代和个性化策展需要启用 AI。
- **按需选择全屏画质**：对话和画廊卡片先请求最长边 640px 的预览；从任何入口打开全屏时优先显示本地已缓存的最高分辨率，不自动下载原图。工具栏可选择最长边 1280px、2400px 或 Commons 原图，也可直接加入画架、在下载失败后重试；下载时显示进度、已下载量和速度，可切回已缓存的画质。滚轮缩放、按住左键拖动，按 Esc 退出图片；若 App 原本已全屏，会保持 App 的全屏状态。卡片右键或更多菜单仍可按需加载 2400px。
- **界面主题**：在“偏好与资料库 → AI 与检索”中选择展厅日光、清晰浅色（高对比文字）、暖纸色、夜间观画或跟随系统；主题偏好保存在可同步资料库中。
- **我的画架**：点击书签立即保存作品资料，桌面版在连续约 12 秒无操作后逐幅下载馆藏提供的最高可显示分辨率；遇到 429 或网络故障时保留收藏并延时重试，也可点击书签立即重试。Cleveland 的档案原件可能是 TIFF，本应用保存的是馆方提供的高清 JPEG。图片下载上限为 512 MB、超时为 5 分钟。画廊卡片仍优先显示本地缩略图；全屏显示实际解码尺寸，并提供 1:1 原始像素查看。右键作品可定位本地文件，或用已下载的 JPG/PNG 原图设置 Windows 桌面壁纸；未下载时设置壁纸会按需下载原图。移除收藏暂时保留本地文件。
- **最近看过**：打开作品详情或全屏欣赏时自动记录；同一作品再次打开会移到最前面，最多保留 50 件，并随本地资料库保存。
- **缩略图容错**：画廊卡片优先使用本地缓存；缓存失败或本地图片无法解码时会回退到 Commons 缩略图地址。只有两种来源都不可用时才显示图片占位。
- **往日对话**：自动保存文本、真实作品元数据、检索词和分页位置；可搜索标题、重新进入、继续检索或删除对话。删除对话不删除收藏。
- **来源与授权**：详情展示作者、年代、授权标记、署名、像素和原始 Commons 页面。缺失授权显示“授权待核实”，不会统一声称所有图片都是 CC0。再使用时请核对来源页面的完整条款。

## 坚果云 / 指定资料库目录

进入 **偏好与资料库 → 资料库与同步**：

1. **迁移到指定文件夹**：选择坚果云内的空文件夹，应用复制现有资料并立即切换使用；原目录保留作备份。
2. **打开已有资料库**：换电脑时，先等待同步完成，再选择包含 `library.json` 的文件夹。
3. 密钥在每台电脑单独配置；应用只在系统配置目录保存资料库位置指针，不把机器绝对路径写进可同步收藏记录。

如果指定文件夹被删除或暂时未同步，启动时会提示重新选择含 `library.json` 的资料库、改用本机资料库，或退出等待同步。切换时会保留原位置记录为 `location.previous.json`，不会删除原资料。

资料库结构：

```text
你选择的资料库/
  library.json          # 对话、画架索引、API 地址/模型、偏好，格式版本 1
  library.backup.json   # 上一次成功保存前的版本
  .write.lock           # 同机写入互斥；不代表跨设备分布式锁
  collection/originals/ # 画架收藏的原图，清理缓存不会触碰
    22174454.jpg
  cache/thumbnails/    # 检索缩略图
  cache/medium-resolution/ # 主动加载的 1280px 预览
  cache/high-resolution/ # 主动加载的 2400px 预览
  cache/originals/     # 主动加载但未收入画架的原图
  images/              # 旧版兼容目录，清理时保留仍被收藏引用的文件
```

图库业务缓存、收藏数据和设置都随此目录移动。在“资料库与同步”可清理临时图片，画架文件与旧版仍被收藏引用的图片会保留。WebView2 自身的运行时缓存仍由系统管理。浏览器预览的 IndexedDB 与桌面资料库相互独立。

**同步约束**：这版采用一个 JSON 快照，适合个人收藏与单机写入，避免 SQLite WAL 被文件同步工具分片同步。保存使用临时文件替换、上次快照备份、同机文件锁和外部修改检测。检测到磁盘内容与上次载入不同，会停止保存并显示错误。请先等待同步完成，再在另一台电脑打开；不要在两台电脑同时编辑。同一时刻的跨设备修改仍需通过坚果云冲突副本人工处理，本版不自动合并。打开已有资料库不会覆盖它；迁移要求目标为空。恢复备份前请退出应用并保留当前文件副本。

## AI 配置

在设置中填写支持 `/chat/completions` 的 **Base URL、模型名称、API Key**，再开启 AI。默认提供常见兼容地址作为编辑起点，不附带任何密钥或服务额度；可换成其他兼容服务。HTTPS 为默认要求，本地 `localhost / 127.0.0.1 / ::1` 服务允许 HTTP。

密钥按服务地址保存在操作系统凭据库，不写入 JSON、IndexedDB 或日志。Rust 发起网络请求，支持操作系统代理设置，避免前端 CORS 和在 WebView 持久化密钥。修改服务地址不会自动沿用另一地址的密钥。灵感寻画会向模型发送对话、候选作品资料、可读取的来源页文字和来源错误；首轮最多深入复核 12 项，之后再解读结果。回答时最多附带 3 张馆藏缩略图，优先采用问题中提到的作品编号；仅对附图做视觉比较，其余依据文字资料。作品讲解会发送当前作品的馆藏缩略图与元数据。模型不支持图片输入时会降级到文字，并提示未读取图片。AI 失败不会隐藏已经搜到的作品。Brave 搜图密钥独立保存在系统凭据库，开启后只向其发送检索词。寻找未收录在本地姓名表中的指定作者时，桌面版可能向 Wikidata 发送至多两个姓名查询（不发送整段对话）；查不到或同名不能证明作者身份，不会阻止馆藏搜索。

## 项目结构与验证

- `src/App.tsx`：发现、对话、画架、历史、详情、右键菜单与设置。
- `src/services/commons.ts`：检索、元数据归一化、HTML 清理、缩略图/高清与 URL 白名单。
- `src/services/ai.ts`：结构化策展规划、画家辨认、持续作品讲解和直接检索回退模式。
- `src/services/artSearch.ts`：多源检索、作者匹配、分页约束及独立来源失败处理。
- `src/services/met.ts`：大都会分页检索与公开图像适配。
- `src/services/webSearch.ts`：Brave 网页图片线索归一化；来源链接与馆藏作品分开存储。
- `src/services/pageEvidence.ts`：受限读取来源页并提取可引用正文。
- `src/services/review.ts`：逐件复核、证据校验与保留／排除／待核实判断。
- `src/services/storage.ts`：Tauri / IndexedDB 存储适配。
- `src-tauri/src/main.rs`：网络边界、密钥、目录选择与迁移、原子保存、冲突检测、受限并发图片缓存。
- `docs/architecture.md`：同类项目调研、架构取舍与待补交互。

```powershell
npm run build
npm test
# 先启动 npm run dev；端到端测试使用已安装的 Chrome
npm run test:e2e
cargo test --manifest-path src-tauri/Cargo.toml
```

前端测试覆盖 URL 白名单、多馆藏 ID 隔离、API 分页与 429 回退、禁止在检索时回退原图、中文画家检索映射、AI 响应校验，以及画架收藏、离线图片读取、全屏缩放、作品讲解与灵感历史分区、设置和网络失败恢复。端到端测试用固定响应保证可重复，`scripts/preview.mjs` 另做真实 Wikimedia 页面检查。

## 当前边界

本版是可扩展的第一版桌面应用。已接入 Wikimedia Commons、Cleveland Museum of Art、Art Institute of Chicago 和 Met，另有可选 Brave 全网图片搜索；尚未提供离线全文索引、跨设备冲突自动合并、缓存容量配额、画架中已移除作品的孤立原图整理、原图批量导出、跨设备加密密钥同步或签名安装器。停止搜集立即取消前端后续处理；已经发出的 Rust HTTP 请求会在返回或超时后结束。AI 服务因用户未提供密钥，需要在本机配置后完成实际供应商联调。

全网搜索会在有限预算内尝试读取公开 HTTPS 来源页正文以辅助筛选；登录、验证码、脚本渲染或被站点拒绝的页面仍可能不可读，也不会自动确认网页图片归属。AI/Brave 的真实供应商调用需要在本机配置密钥；自动化测试使用固定响应验证筛选流程，不能代替实际选图质量评测。
